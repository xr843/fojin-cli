# 数据传输与运维细节

`fojin data` 系列命令的资源上限、超时、并发与版本策略。日常使用不需要读这一页——
[README 的「数据集」节](../README.md#数据集) 讲清了体积和许可就够了。这里是给运维、
容器部署、CI 以及要预估磁盘的人看的。

## 磁盘与传输限额

安装和更新采用**有界的磁盘流式传输**，不在内存中缓冲完整压缩包或数据库：

| 项 | 上限 |
| --- | --- |
| 压缩响应 | 256 MiB |
| 解压后的数据库 | 768 MiB |

更新期间可能临时需要**现用数据库所占空间，外加约 761 MiB 暂存磁盘**
（约 183 MiB 压缩包 + 约 578 MiB 候选数据库）。磁盘紧张的机器请按这个数字预留。

## 超时

| 阶段 | 时限 |
| --- | --- |
| HTTP DNS 解析 | 30 秒 |
| 连接 | 30 秒 |
| 响应头空闲读取 | 60 秒 |
| 响应体空闲读取 | 60 秒 |
| 端到端硬时限 | 15 分钟 |

端到端硬时限跨重定向，覆盖从 DNS 到响应体读完的全过程。

## 并发

同一数据目录上的**首次安装、更新和清理**按 single-flight 串行执行，等待者最多等
**20 分钟**。

`data.sqlite.lock` 是永久保留的协调文件，无害；`fojin data clean` 会**有意保留**它。

## 数据版本固定

当前二进制把官方下载地址、SHA-256 与兼容元数据固定在 `data-v1`。因此：

- `fojin data update` 只会重新获取这份固定数据，**不会**自动切换到未来的数据主版本；
- 版本、归一化规则或查询所需 schema 不兼容的数据会被拒绝；
- 程序的渲染路径可兼容未来新增的语言行，但**渲染兼容不等于官方更新通道无需升级**。
  上游 MITRA-parallel 出现新语言，不代表当前二进制会自动获得它；未来的数据版本可能
  要求升级二进制，或明确切换数据发布。

## 置信度字段

`data-v1` 里所有对齐的置信度均为 1.00，不具区分度，因此人类可读输出不再逐行标注
`[MITRA 1.00]`；`--json` 的 `confidence` 字段照常输出。未来数据若提供真实分数，低于
1.00 的会自动重新显示。

## 中断恢复

写入数据时被中断（Ctrl-C、断电等）留下的回滚日志，会在查询打开数据时由 SQLite 自动
回滚。数据确实不可写而无法回滚时，报错会说明真实原因与处理办法。`fojin data clean`
与 `fojin data update` 会一并清理活跃数据的 `-journal` / `-shm` / `-wal` 边车。

## 相关命令

```bash
fojin data status   # 本地数据状态(位置/大小/版本/行数统计)
fojin data verify   # 校验版本、SQLite 与 FTS 完整性
fojin data update   # 重新下载数据(覆盖本地)
fojin data clean    # 删除本地数据,释放 578 MB
```
